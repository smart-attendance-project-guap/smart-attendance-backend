# Досрочное завершение: статусы, Telegram, статистика, Excel

Согласованное правило для Smart Attendance:

- `finishedAt` закрывает QR и освобождает аудиторию, преподавателя, участвующие группы. Преподаватель может подтвердить или отклонить существующие `PENDING` отметки после завершения.
- Плановый `endsAt` — крайний срок для фиксации **пропуска без отметки**. Если преподаватель завершил пару раньше, но `endsAt` ещё не наступил, показываем **«Нет отметки»**, а не «Пропуск».
- Telegram `LESSON_MISSED` формируется только для **завершённых** занятий не раньше `endsAt` и только студентам участвующих групп, у которых **нет никакой записи Attendance**. `PENDING`, `PRESENT`, `LATE`, `REJECTED` исключаются из уведомления о пропуске. Обрабатывается плановое окончание и завершение преподавателем позже планового окончания. Повторные уведомления блокирует уникальность `userId/lessonId/type`.
- `ATTENDANCE_REJECTED` ставится в очередь при решении преподавателя, независимо от планового времени окончания.
- Статусы для UI/Excel:
  - запись отсутствует, `endsAt` ещё впереди: **«Нет отметки»**;
  - запись отсутствует, `endsAt` наступил и пара завершена преподавателем: **«Пропуск»**;
  - `PENDING`: **«Ожидает проверки»** (не считать подтверждённым пропуском);
  - `PRESENT`/`LATE`: подтверждённое посещение;
  - `REJECTED`: **«Отклонено»** (не посещение; в итоговом счётчике пропусков учитывается после `endsAt`).

## Поля API для кабинета

`GET /api/attendance/lesson/:id`:
`absentStudents` — студенты без записи только после завершения пары и планового окончания;
`unmarkedStudents` — студенты без записи до наступления итогового срока;
`attendanceFinalized` — завершилась ли пара и наступил ли плановый конец.
Студенты с `PENDING` присутствуют в `attendances`, **не** в `absentStudents`.

`GET /api/attendance/teacher/lessons/stats`:
для каждого элемента `groupStats` дополнительно возвращаются `pendingStudents`,
`rejectedStudents`, `unmarkedStudents` (до планового конца), `missedStudents`
(после планового конца), а у пары — `attendanceFinalized`.
Существующие `attendedStudents`, `totalStudents`, `attendancePercentage` не переименованы.
`attendancePercentage` означает **долю подтверждённых**, а не автоматически
«окончательный процент отсутствующих», если `attendanceFinalized=false`.

`GET /api/attendance/stats`:
`missedLessons` учитывает закончившиеся по `endsAt` и завершённые преподавателем пары
без отметки либо с `REJECTED`; `pendingLessons` и `unmarkedLessons`
показываются отдельно.

## Текст предупреждения преподавателю (предложение)

«Занятие завершено досрочно. QR-код закрыт. Ожидающие отметки можно
проверить после завершения. До планового времени окончания студенты без
отметки отображаются со статусом „Нет отметки“. После планового окончания
отсутствие отметки считается пропуском, и Telegram-уведомление отправляется
только студентам, не оставившим отметку».

## Проверки

`npx.cmd tsx scripts/smokeSharedTelegramNotifications.ts` —
отложенные уведомления, `PENDING`/`REJECTED`, обе группы общей лекции, дедупликация.

`npx.cmd tsx scripts/smokeFinalBackend.ts` — Excel до и после планового конца.

`npx.cmd tsx scripts/smokeSharedLectures.ts` — досрочное завершение,
подтверждения и статистика. Запускать только с `DATABASE_URL`
на `smart_attendance_mvp_test`.
